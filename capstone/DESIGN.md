# Одностраничная записка: дизайн minietl

**Назначение.** Инструмент на Python 3.11 собирает потоковые ETL-конвейеры из JSON, отделяя ошибки записей от ошибок инфраструктуры. Каждый solution.py D1/D2 содержит реализацию своего задания. Capstone находится в собственном solution.py и импортирует эти решения напрямую без копирования логики; common.py содержит только служебный ввод-вывод.

**Наследование.** Connector — абстрактный контекстный менеджер; Source и Sink специализируют его контрактами read и write. CsvSource, JsonLinesSource и InMemorySource реализуют Source. JsonLinesSink реализует Sink, а CsvSink переиспользует его управление файлом, изменяя сериализацию. InMemorySink хранит копии словарей; BatchSink, DryRunSink и WarehouseSink специализируют его поведение. PartitionedSink реализует Sink и распределяет записи по датам. Transform — независимый ABC; Filter, Rename, Cast, Deduplicate, NormaliseDate и TransformChain реализуют apply. Check — ABC проверок; NotNull, Unique, InRange, MatchesPattern и Freshness возвращают одинаковый CheckResult. Order — frozen dataclass без искусственной иерархии. MissingField, InvalidAmount, DuplicateKey и InvalidDate наследуют ValidationError, чтобы ошибки данных можно было перехватывать общей категорией. RetryExhausted и ConfigError отдельно описывают исчерпание попыток и ошибки сборки.

**Композиция.** Pipeline содержит Source, последовательность Transform и Sink; оператор | создаёт композицию, а into исполняет её. TransformChain содержит другие Transform. QualitySuite содержит произвольные Check и работает с ними полиморфно. PartitionedSink содержит отдельные JsonLinesSink для партиций. Capstone оркестрирует библиотечные компоненты, staging, файловый журнал и отчёты; он не наследует Pipeline ради добавления управления транзакцией. Retry — декоратор функции с внедряемыми sleep, clock и источником jitter. Реестры базовых классов создают плагины по именам через __init_subclass__; подписи конструкторов дают точные пути ошибок JSON. Пользовательский конфиг не исполняется как код.

**LSP.** Все Source возвращают итератор словарей и поддерживают общий жизненный цикл. Все Sink принимают любой iterable, в том числе пустой и однопроходный генератор, возвращают int и предоставляют безопасный flush. BatchSink не требует минимум 100 записей: он принимает малые порции и дописывает буфер при flush/close. Счётчик означает число принятых записей; цена буферизации — отложенная долговечность. DryRunSink возвращает число обработанных записей, сохраняя семантику сухого запуска. WarehouseSink реализует обещанный flush. Transform не меняет входной словарь, возвращает dict либо None; состояние Deduplicate допустимо контрактом и сбрасывается явно. Check всегда возвращает CheckResult с максимум пятью примерами. Параметризованные контракты охватывают каждый зарегистрированный источник, приёмник, transform и check; матрица 3 × 3 проверяет взаимозаменяемость основных коннекторов.

**Надёжность.** Decimal исключает двоичную погрешность денежных сумм; UTC устраняет ошибки дат партиций и сессий через полночь. Ошибки отдельных записей считаются и помещаются в карантин. Файл сначала полностью обрабатывается приватно, затем публикуется под стабильными именами; атомарный watermark подтверждает завершение. Повтор после сбоя заменяет те же shards. Журнал пути и SHA-256 принимает поздние файлы. Источник повторяется только при ConnectionError/TimeoutError. Check error проваливает статус запуска, warning только сообщает; проверки повторно читают весь подтверждённый набор. Ограничения: один писатель, отсутствие общей транзакции публикации нескольких файлов, дисковый журнал без автоматической очистки, память для ключей дедупликации и сортировки D1.6. Эти ограничения не меняют интерфейсные контракты.
