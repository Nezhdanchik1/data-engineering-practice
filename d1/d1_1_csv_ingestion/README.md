## Решения и ограничения

Ошибки CSV-парсера (слишком длинное поле или неверные кавычки) учитываются как InvalidCSV с номером строки; обработка следующих записей продолжается. Для таких ошибок поля не удалось разобрать, поэтому rejects.csv содержит диагностическую причину вместо значений строки. UTF-8 BOM в заголовке поддерживается.

D1.1 проверяет наличие полей, Decimal (конечный, >= 0) и дубликаты принятых ключей. Email и даты проверяются следующими заданиями. При ошибке UTF-8 повторное декодирование выполняется ровно один раз с fallback_encoding. Полное декодирование до записи исключает частичные результаты; ограничение — размер CSV должен помещаться в память.
