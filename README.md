# minietl — Data Engineering на Python

Учебный проект по Data Engineering: задания **D1.1–D1.6**, **D2.1–D2.6** и итоговый инструмент **minietl**. Выполнены уровни Core, Advanced и Challenge.

Программа читает файлы заказов и кликов, преобразует записи, сохраняет ошибки в карантин, распределяет результат по UTC-датам и проверяет качество данных. Повторный запуск неизменённых файлов не добавляет записи заново.

## Требования

- Python **3.11 или новее**.
- Код решений использует стандартную библиотеку Python.
- Для тестов нужен **pytest**, указанный в requirements-dev.txt.

Для Windows включены данные часовых поясов IANA в `d1/d1_2_dates/timezones.zip`; их читает стандартный zoneinfo. Устанавливать Python-пакет tzdata не требуется. [Лицензия данных](d1/d1_2_dates/TZDATA_LICENSE.txt).

## Быстрый запуск

Скачайте или склонируйте репозиторий и откройте терминал в его корневой папке — там, где находятся minietl.py и tasks.txt.

```bash
python --version
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m minietl capstone/configs/orders.json
python -m minietl capstone/configs/clicks.json
```

Если Python в вашей системе запускается командой python3, используйте её вместо python. Подготовленная локальная папка .tools не включается в репозиторий и для запуска скачанного проекта не требуется.

Для текущего кода ожидается **212 пройденных тестов**. Проверено на Python 3.11.9.

## Примеры результатов

Входные данные содержат неделю синтетических заказов и кликов, ошибочные записи, повреждённый файл и отдельный поздний файл.

Первый запуск с исходными примерами и чистым состоянием:

| Набор | Прочитано | Записано | Отклонено | Намеренно отброшено |
|---|---:|---:|---:|---:|
| Заказы | 45 | 14 | 24 | 7 |
| Клики | 28 | 21 | 7 | 0 |

Ошибочные строки в примерах намеренные. Успешный запуск может иметь rejected > 0: ошибки учтены, подходящие записи загружены, настроенные проверки результата пройдены.

Повторите ту же команду:

```bash
python -m minietl capstone/configs/orders.json
```

Новых записей будет **0**, но качество уже загруженного набора проверится снова. Если исходные данные изменены, числа могут отличаться от таблицы.

## Где смотреть результат

Результаты создаются в `capstone/work/orders/` и `capstone/work/clicks/`:

| Путь | Содержимое |
|---|---|
| output/year=.../month=.../day=.../ | Очищенные JSONL-записи по UTC-дате. |
| rejects.jsonl | Отклонённые записи с причиной, шагом обработки и исходным файлом. |
| watermark.json | Подтверждённые версии обработанных файлов. |
| report.json | Время запуска, длительность, счётчики по шагам и результаты качества. |
| watermark_batches/ | Внутренние данные для проверок и восстановления. |

В отчёте rows_in/rows_out/rejected/dropped относятся к текущей загрузке, quality_rows — ко всему подтверждённому набору. Отчёт заменяется при каждом запуске. Каталог work исключён из Git.

Код завершения CLI: **0** при успехе, **1** при ошибке запуска или провале проверки качества уровня error. Warning только отражается в отчёте. Неверная запись отправляется в карантин, не останавливая обработку остальных; ошибки конфигурации или инфраструктуры завершают запуск с сообщением.

    solution.py          реализация итогового CLI

    tests/               интеграционные и контрактные тесты

В каждом задании D1/D2 есть **solution.py с реализацией**, **test_solution.py** и **README.md**. Capstone переиспользует эти решения через импорты; нужно сохранять структуру всего проекта.

| Группа | Содержание |
|---|---|
| D1 Core | CSV и карантин; даты и UTC-партиции; очистка текста и маскирование. |
| D1 Advanced | Инкрементальная загрузка; повторы с exponential backoff. |
| D1 Challenge | Построение сессий кликов. |
| D2 Core | Модель Order; источники/приёмники; цепочки преобразований. |
| D2 Advanced | Проверки качества; исправление нарушений LSP. |

Задания C1/C2 и warm-up W1–W20 не входят в реализованный объём. Синтетические примеры созданы для этой работы, поскольку отдельных provided-файлов в исходной папке не было.

## Запуск отдельных проверок

```bash
python -m pytest d1 -q
python -m pytest d2 -q
python -m pytest capstone/tests -q
python -m pytest d1/d1_1_csv_ingestion -v
```

Тесты используют временные данные. Проверяются нормальные записи, ошибки парсеров и кодировки, матрица источников/приёмников 3 × 3, контракты компонентов, повторы, поздние файлы и сбои чтения/публикации.

## Принятые решения и ограничения

- Денежные суммы обрабатываются как Decimal, в JSON сохраняются строками без потери десятичной точности.
- Выходные метки времени и папки используют UTC. Наивное время интерпретируется в указанной зоне источника.
- Watermark capstone учитывает путь и SHA-256 файла, поэтому поддерживает поздние поступления. Один процесс должен владеть конкретным watermark.
- Deduplicate действует внутри входного файла; Unique обнаруживает повторы между файлами, но сам их не удаляет.
- Качество проверяется после загрузки. Провал error помечает запуск failed без отката подтверждённых данных.
- Публикация нескольких файлов не является общей транзакцией; после сбоя повтор восстанавливает результат в предусмотренных сценариях.
- D1.1 декодирует CSV целиком ради резервной кодировки; построение сессий хранит события для сортировки. Источники D2 читают постепенно.
- Маскирование PII и построение сессий доступны отдельными API D1.3/D1.6; конфиги примеров автоматически их не вызывают.
- Удаление входного файла не удаляет уже загруженные записи. Автоочистка старых внутренних поколений не реализована. WarehouseSink — учебная модель в памяти без внешней БД.
